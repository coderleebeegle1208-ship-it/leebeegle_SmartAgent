# 컴포저 영역 정돈 시안 3개

## 대상
폰 앱 화면 맨 아래 고정된 입력 영역. 현재 세 줄로 쌓여 있다:
1. 필 컨트롤 줄 — `Claude ▾` `권한 자동 ▾` `교차 모델 ▾` (좌) / `검토` 토글 + 사용량 링 (우)
2. 교차 모델 파이프라인 줄 — `Haiku 최신·4.5 판단 → Opus 최신·5 계획·높음 → Sonnet 최신·5 실행·기본`
3. 입력 줄 — `+` 버튼 / 텍스트 입력창 / `보내기` 버튼

## 유지 조건 (모든 안 공통)
- 앱 전체 톤(흰 배경, 보라 포인트 `--accent`)과 `public/style.css :root` 색 토큰만 사용. 새 hex 금지.
- 이모지 금지. 사진에 있는 실제 한국어 라벨(Claude, 권한 자동, 교차 모델, 검토, 판단, 계획, 실행, 높음, 기본, 보내기, 지시를 입력하세요…) 그대로 사용.
- 모든 텍스트 라벨 12px 이상.
- 특정 회사 앱을 흉내 내지 않는다 — 색·서체·간판 스타일이 아니라 open-design의 `clean`/`minimal` 원칙(여백으로 분리 → 그다음 선/그림자, 계층 평탄화 금지, 4·8·12·16 간격)만 참고.

## 어수선한 원인 진단
세 줄이 서로 다른 시각 언어를 쓴다: 테두리 필(줄 1) / 밑줄 텍스트 셀렉트(줄 2) / 두꺼운 테두리 입력창(줄 3). 라벨이 10~11px로 작고, 파이프라인은 2단 스택 + 화살표라 높이를 많이 먹는다.

## 3가지 방향 (골격이 서로 다름 — 스킨 교체 아님)

### A — 한 카드 트레이 (A-tray.html)
입력창을 큰 둥근 카드 하나로 통합. 카드 위쪽은 테두리 없는 텍스트 입력 영역, 아래쪽은 툴바 한 줄(`+` / `Claude` / `권한 자동` / `교차 모델` … `검토` 토글 / 사용량 링 / 원형 전송 버튼). 파이프라인 정보는 카드 바로 위 한 줄 텍스트로 축약: `판단 Haiku 4.5 → 계획 Opus 5·높음 → 실행 Sonnet 5·기본`. 3줄 → 2블록으로 줄어든다.

### B — 선 없는 틴트 블록 (B-tint.html)
모든 1px 테두리를 제거하고, 컨트롤을 `--surface` 채움 + 10px 라운드로 통일해 색 대비만으로 구분. 칩은 고스트 필 스타일. 파이프라인은 폭이 같은 3칸 스텝 카드(위: 판단/계획/실행, 중간: 모델명, 아래: 강도를 보라색 소문자로) — 화살표 없이 좌→우 배치만으로 흐름을 표현. 입력창도 채움형 배경, 전송은 44px 원형 아이콘 버튼.

### C — 세그먼트 바 + 한 줄 파이프라인 (C-segment.html)
상단 3개 칩을 얇은 구분선이 있는 하나의 둥근 세그먼트 컨트롤로 묶고, 오른쪽에 검토 토글과 사용량 링을 같은 높이로 정렬. 파이프라인은 스택 없이 한 베이스라인 위 한 줄로: 모델명은 진한 색, 단계 라벨은 옅은 색, 강도는 보라색. 입력창 안 오른쪽에 전송 버튼을 필 형태로 내장하고, `+` 버튼은 입력창 왼쪽 바깥에 둔다.

## 캡처
`mcp__approver__capture`로 각 HTML을 390px 폰 프레임 중심, height 640 안팎으로 찍어 3장 모두 폰 화면에 표시한다. 찍기 전 자체 점검: 이모지 없음, `:root` 외 새 hex 없음, 12px 미만 라벨 없음, 가로 스크롤 없음.
