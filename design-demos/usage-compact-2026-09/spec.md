# 홈 상단 Claude 한도 영역 압축 시안 3개

## 대상
홈 화면 맨 위, `.pc`(이름·Connected·Windows PC·CPU/RAM) 바로 아래 있는 `.usage` 블록.
현재 5시간 세션 / 주간·전체 모델 / 주간·Fable 3줄이 항상 펼쳐져 있고, 각 줄마다 리셋 시각이 딸려
나온다. 폰 폭(≤400px)에서는 리셋 시각이 다음 줄로 내려가 한 줄이 두 줄이 되어 총 **6줄**을 차지한다.

## 진단
- 3행 × (라벨 + 바 + % + 리셋 줄바꿈)로 6줄까지 늘어난다.
- 리셋 시각은 매번 봐야 하는 정보가 아닌데 항상 노출되어 있다.
- `.pc`와 `.usage`가 각각 하단 헤어라인을 가져서 2단 헤더처럼 보인다.
- 결과적으로 한도 정보가 첫 화면 절반을 차지해서 진짜 보고 싶은 에이전트 목록이 아래로 밀린다.

## 유지 조건 (모든 안 공통)
- `public/style.css :root` 색 토큰만 사용, 새 hex 금지.
- 이모지 금지. 모든 라벨 12px 이상.
- 사진에 있는 실제 값(5시간 0%, 주간·전체 모델 68%, 주간·Fable 100%, 리셋 Sep 17 5:50am / Sep 19 9:59pm) 그대로 사용.
- 레이아웃 골격(‎`.pc` → 한도 영역 → 필터 레일 → 워크스페이스 목록) 유지, 앱 토큰 그대로.

## 3가지 방향 (골격이 다름 — 스킨 교체 아님)

### A — iOS 설정 행 (A-ios.html)
`.usage`를 44px 한 줄로 압축. 왼쪽 라벨 "Claude 한도", 가운데 세 개의 짧은 미니 미터
(5시간 0% / 주간 68% / Fable 100%, 각 12px 텍스트 + 3px 바), 오른쪽 iOS 디스클로저 셰브론.
탭하면 같은 자리에서 기존 3행(리셋 포함)이 펼쳐진다(`<details>`). 파일 안에 접힌 상태 프레임과
펼친 상태 프레임을 각각 하나씩 넣어 두 상태를 모두 보여준다.

### B — Linear 인라인 미터 (B-linear.html)
별도 `.usage` 블록과 헤어라인을 없애고 `.pc` 안 3번째 줄로 흡수한다. "Windows PC · 마지막 동기화"
아래에 5시간 / 주간 / Fable 세 개의 고스트 필(‎`--surface` 채움 + 하단 2px 진행선)을 나란히 둔다.
헤더 전체가 한 블록으로 보이고, 탭하면 리셋 시각이 담긴 카드가 아래로 열린다는 힌트 문구를 둔다.

### C — Claude 앱 요약 스트립 (C-claude.html)
`.usage`를 40px 스트립 하나로: 컴포저에서 쓰는 `.usage-ring`(conic, 5시간 기준) + 텍스트
"5시간 0% · 주간 68% · Fable 100%"(가장 높은 값만 강조) + 오른쪽 "자세히" 텍스트 버튼.
탭하면 컴포저의 사용량 팝오버와 같은 상세 카드가 스트립 아래로 열린다.

## 캡처
`mcp__approver__capture`로 각 HTML을 `width 500, height 640`으로 찍어 3장(A는 접힘/펼침 포함해
프레임이 더 있을 수 있음) 모두 폰 화면에 전송한다. 찍기 전 점검: `:root` 외 새 hex 없음, 이모지
없음, 12px 미만 라벨 없음, 가로 스크롤 없음.

## 선택 후 적용
1. `direction-approved.md`에 날짜·선택 원문·적용 파일 기록.
2. `public/style.css` 83~94행(+ 440px 반응형 517~519행) 교체.
3. `public/app.js`의 `usageHTML()`(598~609행) 마크업을 선택 안에 맞게 교체. 슬롯 라벨은
   `usageSlots('claude')`를 재사용해 5시간/주간/Fable로 통일한다. `#usage` id는 유지
   (`loadUsage()`가 계속 그 id로 갱신한다).
4. 펼침/팝오버는 A는 `state.usageOpen` + localStorage(`ar_usage_open`) 패턴, B/C는
   `renderHome()`에 탭 핸들러를 추가하고 `usagePopupHTML()`을 재사용한다.
5. `README.md`의 한도 표시 관련 문장이 있으면 한 줄만 갱신한다.

## 검증
1. `npm test`.
2. `npm start` 후 홈 화면을 `width 500`으로 캡처해 상단이 2줄 이하인지, 0%/68%/100% 색 구분,
   탭 시 리셋 시각 노출, ≤400px에서 줄바꿈·가로 스크롤 없는지 확인.
3. 에이전트(컴포저) 화면의 사용량 링·팝오버가 그대로 동작하는지 확인.
